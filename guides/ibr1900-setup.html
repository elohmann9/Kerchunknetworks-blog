🏁 Start Here: Hardware Setup
First Time? Follow these physical setup steps before trying to log into the software. Pull the SIM card before configuring locally — see Factory Reset section below.
  • Power: Connect the 4-pin Molex power connector. Amber LED = booting, solid green = healthy. Note: unit may still show amber even when fully functional — try hitting 192.168.0.1 anyway.
  • Pull SIM card before configuring locally. With the SIM inserted, the unit tries to connect to NetCloud Manager and the local UI becomes sluggish and unreliable.
  • Antennas:
    • Connect 4x Cellular/5G antennas to "Cellular" ports.
    • Connect 2x WiFi antennas to "WiFi" ports.
    • Connect 1x GPS antenna to "GPS" port (Critical for tracking!).
  • Laptop Connection: Connect your PC via Ethernet cable to LAN Port 1 (not the WAN port).
  • Starlink (if applicable): Connect Starlink Ethernet adapter to WAN Port.
    • 🔄 Factory Reset & Default Credentials
    When to factory reset: If you've lost access, made a config mistake, or the unit is coming from another deployment. Hold the reset button for 45 seconds, then wait 1–2 minutes for it to fully boot.
    Setting Default Value Notes
    URL 192.168.0.1 Connect via LAN port only
    Username admin
    Password admin After factory reset
    Power LED: amber Booting Wait for green or just try the IP
    Power LED: solid green Healthy
    Pro tip: After reset, pull the SIM card before doing anything else. The unit will try to phone home to NetCloud and the local UI becomes nearly unusable while it does that.

    ⚠️ VLAN Warning — Read This Before Touching Anything
    🚨 DO NOT MANUALLY CREATE VLAN INTERFACES.

    VLAN tagging is handled automatically by the router when you assign SSIDs to networks. Manually creating VLAN interfaces has caused units to lose all connectivity and require a factory reset. This has happened 4+ times. Do not do it.

    The only pre-existing VLAN interfaces are wan (VID 1) and lan (VID 2). Leave them alone. Do not rename them, do not add more. Just assign your SSIDs to the correct network via the Interfaces tab and the router handles the rest.
    If you think you need to create a VLAN interface manually — you don't. Assign the SSID to the correct network instead. If it still doesn't work after that, factory reset and start fresh rather than digging deeper into VLAN settings.
    📋 Safe Configuration Order
    Follow this exact sequence. Deviating from it — especially doing VLAN interfaces early or in the wrong order — is how units get bricked.
    Step 1: Initial Access

    Log into 192.168.0.1 with your PC connected via Ethernet to the LAN port (not WAN). Default credentials: admin / admin after factory reset.

    Step 2: Configure Primary LAN IP

    Edit Primary LAN directly — do not create a new network.

    • Go to: Networking → Local Networks → Local IP Networks → Edit Primary LAN
    • IPv4 Settings → change IP to 10.7.X.1 (use unit's octet)
    • Subnet: 255.255.255.0
    Step 3: Configure DHCP (Same Editor, Don't Save Yet)

    While still in the same Primary LAN editor:

    • IPv4 DHCP → set range: 100–200
    • Add Custom Option 6: 1.1.1.1,8.8.8.8 (DNS servers)

    Now hit Save. You will immediately lose your browser connection — this is expected.

    Step 4: Reconnect to New IP

    Set your PC to a static IP:

    IP Address: 10.7.X.50 Subnet: 255.255.255.0 Gateway: 10.7.X.1 DNS: 1.1.1.1

    Then navigate to 10.7.X.1 in your browser to confirm it loads.

    Step 5: Add Guest Network

    Add a new local network for guest traffic:

    • IP: 10.8.X.1 / subnet 255.255.255.0
    • DHCP range: 100–200
    • Custom Option 6: 1.1.1.1,8.8.8.8
    Step 6: DO NOT Create VLAN Interfaces
    🚨 Skip this. Do not go into VLAN Interfaces and add anything. The router handles VLAN tagging automatically when you assign SSIDs in the next step. Creating VLAN interfaces manually will brick the unit.
    Step 7: Configure WiFi SSIDs

    Go to Networking → WiFi → Wireless Settings and configure three SSIDs:

    • WFPD-[UNIT] — 5GHz, assigned to Primary LAN (ops network)
    • WFPD-[UNIT]-GUEST — 2.4GHz, assigned to Guest network
    • WFPD-SCENE — 5GHz, assigned to Scene mesh network

    Assign each SSID to the correct network via the Interfaces tab in the SSID editor.

    Step 8: Add Scene Mesh Network

    Add a third local network for scene mesh:

    • IP: 10.7.99.1 / subnet 255.255.255.0
    • DHCP range: 100–200
    • Assign WFPD-SCENE SSID to this network
    Step 9: Configure WAN Failover

    See the WAN Failover section below for exact settings.

    Short version: Connection Manager → WAN Verify → Active Ping → 8.8.8.8 / retry interval 5s / retry count 3.

    Step 10: Configure Guest Isolation

    See the Guest Isolation section below.

    Short version: Security → Zone Firewall → Zone Forwarding → Add rule: Guest LAN Zone → Primary LAN Zone → Default Deny All.

    Step 11: Set Static DHCP Reservation for Tablet Command iPad

    Reserve 10.7.X.50 for the Tablet Command iPad using the iPad's MAC address.

    Path: Networking → Local Networks → DHCP Leases → Add Reservation

    Note: You need the iPad's MAC address to complete this step. Get it from Settings → General → About → Wi-Fi Address.
    Step 12: Backup Configuration

    Always export and save the config after a successful build:

    • Path: System → Configuration → Export Configuration
    • Save as: IBR1900_[UNIT]_Backup_YYYY-MM-DD.json

    🔒 Guest Network Isolation
    Goal: Guest devices can reach the internet but cannot reach the ops network (Primary LAN). One rule handles this.
    Zone Firewall — Guest Isolation Rule

    Path: Security → Zone Firewall → Zone Forwarding

    Add one rule:

    Setting Value
    Source Zone Guest LAN Zone
    Destination Zone Primary LAN Zone
    Filter Policy Default Deny All
    That's it. The default rules already handle WAN ↔ LAN correctly. This one explicit rule is all that's needed for guest isolation. Do not create additional rules unless you have a specific reason.
    📡 WAN Failover Configuration
    Method: Active Ping (not passive DNS). Active ping is more reliable for detecting real connectivity loss. Both SIM and WiFi WAN should be set to Always On with strict priority failover.
    WAN Verify / Active Ping Settings

    Path: Networking → Connection Manager → WAN Verify

    Setting Value Notes
    Verify Method Active Ping Do not use passive DNS
    Ping Target 8.8.8.8 Google DNS — reliable target
    Retry Interval 5 seconds
    Retry Count 3 Fail after 3 missed pings (~15s)
    Connection State Always On Apply to both SIM and WiFi WAN
    Smart WAN Selection Disabled Use strict priority failover instead
    QoS AutoQoS (default) Leave as-is
    Interface Priority
    • Priority 1 (Primary): Cellular SIM
    • Priority 2 (Failover): Starlink / WiFi as WAN

    Both interfaces should be set to Always On — the router uses the priority order to decide which to route through, and automatically fails over if the primary loses ping verification.

    📌 Static IP Reservations

    Every unit follows this standard reservation layout. DHCP reservations are set by MAC address — you need the device's MAC before you can lock in the reservation.

    Address Device How to Set
    10.7.X.1 Cradlepoint gateway (automatic) Set during Primary LAN config — not a DHCP reservation
    10.7.X.50 Tablet Command iPad DHCP reservation by MAC address — need iPad MAC first
    10.7.X.51–.60 APX6000XE radios (future ROIP) Reserve range — do not assign until ROIP is deployed
    10.7.X.100–.200 DHCP pool Set in Primary LAN DHCP settings
    Getting the iPad MAC: Settings → General → About → Wi-Fi Address. Use this MAC for the DHCP reservation, not the cellular/Bluetooth address.
    Path for DHCP reservations: Networking → Local Networks → DHCP Leases → Add Reservation
    🛰️ Dual GPS Configuration
    Why Dual GPS? We configure two separate GPS clients because Versaterm (CAD) and Tablet Command (Tactical) require different data formats and update intervals.
    Global GPS Settings

    Path: System → Administration → GPS

  • Enable GPS: ✅ Checked
  • Enable GPS Lock LED: ✅ Checked (Helps troubleshooting)
  • Enable GPS Keepalive: ✅ Checked (Prevents "disappearing" units)
  • Enable GPS verbose logging: ☐ Unchecked
  • TAIP Vehicle ID: Set to unit-specific ID (e.g., 3302 for unit 3302)

    • Client 1: Versaterm (Dispatch/CAD)

    Versaterm Configuration
    Setting Value Notes
    Client Name Versaterm
    Server avl.smc911.org San Mateo County AVL
    Port 12345
    Protocol UDP Faster, lower overhead
    Stored Sentences 1000 ~50 min buffer
    Time Interval 3 seconds High frequency updates

    NMEA Settings (Language Page):

  • Language: NMEA
  • Prepend Unique Identifier: ✅ Checked (Critical for Versaterm!)
  • Unique Identifier Definition: Custom — enter unit ID (e.g., "3302")
  • Sentence Types:
    • ✅ RMC (Recommended Minimum) — ONLY this one needed.
    • ☐ GGA/GNS/VTG — Leave OFF to save data.

    • Client 2: Tablet Command (Tactical Map)

    Tablet Command Configuration
    Setting Value Notes
    Client Name Tablet Command
    Server avl.tabletcommand.com
    Port 12121 Different from Versaterm
    Protocol UDP
    Stored Sentences 1000
    Time Interval 10 seconds Slightly slower update rate

    NMEA Settings (Language Page):

  • Language: NMEA
  • Include Unique Identifier: ✅ Checked (Appended at end)
  • Prepend Unique Identifier: ☐ Unchecked
  • Unique Identifier Definition: System ID (Router Serial/MAC)
  • Sentence Types:
    • ✅ GGA (Position Fix)
    • ✅ GNS (GNSS Fix)
    • ✅ RMC (Recommended Minimum)
    • ✅ VTG (Velocity/Track)
    • Optimization: Reduce Data Usage
    Pro Tip: Configure "Stationary Settings" to save cellular data when the apparatus is parked.

    Recommended Settings:

    • Stationary Time Interval: 30–60 seconds (slower updates when parked)
    • Stationary Event Threshold: 60 seconds (wait 1 min before slowing down)
    • Stationary Distance Threshold: 20 meters (ignore GPS drift)

    Impact: Reduces GPS data usage by ~75% while maintaining instant tracking when the vehicle moves.

    🧪 Testing & Validation
    Step 1: Network Connectivity
  • Confirm 10.7.X.1 loads in browser from ops SSID
  • Confirm internet connectivity from ops network: ping 8.8.8.8
  • Confirm guest devices can reach internet but cannot ping 10.7.X.1
  • Confirm WFPD-SCENE SSID connects to 10.7.99.0/24 range
    • Step 2: WAN Failover Test
    Test Procedure: Document failover timing for emergency response planning.
    1. Disable primary cellular interface temporarily
    2. Confirm automatic switch to secondary WAN (Starlink/SIM2)
    3. Verify GPS continues reporting during failover
    4. Test internet connectivity on backup WAN
    5. Re-enable primary and confirm failback
    6. Document total failover time

    Expected Results:

    • Failover time: ~15–30 seconds (3 failed pings × 5s interval)
    • GPS services continue uninterrupted
    • Automatic failback when primary restored
    Step 3: GPS Service Testing
    Testing Time: Verify with dispatch/Versaterm during normal business hours. Tablet Command AVL may also have specific active-hours behavior.
  • Verify GPS lock with 4+ satellites
  • Confirm Tablet Command server connection
  • Verify Versaterm server connection
  • Check GPS packet transmission is incrementing
  • Test position accuracy vs. known location
  • Confirm correct Unit ID is transmitting

    • Verification Commands (local router CLI):

    show location clients show location statistics show gps status
    Step 4: Static DHCP Reservation Verification
  • Connect Tablet Command iPad to WFPD-[UNIT] SSID
  • Verify iPad receives 10.7.X.50 (not a random DHCP address)
  • If wrong address: confirm iPad MAC matches what's in the reservation
    • 🚨 Troubleshooting Guide
    Lost Connectivity After Configuration Change

    Most likely cause: Manual VLAN interface was created. See the VLAN Warning section — this has happened 4+ times.

    1. Try setting PC to a static IP in the new subnet and hitting the gateway IP
    2. If the UI is unreachable, factory reset is the fastest path forward
    3. After reset, pull SIM before reconfiguring and follow the Safe Configuration Order exactly
    GPS Services Not Reporting

    Diagnostic Steps:

    1. Check GPS Status: Status → Location → GPS Status
      • Satellites: Should show 4+
      • Fix Quality: Should be "3D Fix"
    2. Test Server Connectivity:
      ping avl.tabletcommand.com ping avl.smc911.org
    3. Check Client Status: Location → GPS Clients → [CLIENT] → Status
      • Last Transmission: Should be recent
      • Packets Sent: Should be incrementing

    Solutions:

    • Restart GPS client: restart location-client [CLIENT_NAME]
    • Check antenna connections
    • Verify server addresses haven't changed
    • Contact dispatch to confirm reception on their end
    WAN Failover Not Working

    Diagnostic Steps:

    1. Verify both interfaces show "Connected" in Status → WAN → Interfaces
    2. Confirm Active Ping is configured (not passive DNS)
    3. Make sure Smart WAN Selection is off — it interferes with strict priority failover
    4. Confirm both interfaces are set to Always On
    Local UI Slow / Unresponsive

    Almost certainly: SIM card is inserted and the unit is trying to connect to NetCloud Manager. Pull the SIM, wait 30 seconds, reload the UI. It'll be snappy again.

    Emergency Procedures
    Critical System Failure: If primary communications fail during emergency operations.

    Emergency Recovery Steps:

    1. Switch to radio backup communications immediately
    2. Document system failure time
    3. Quick checks: power connections, antenna connections
    4. Router reboot: System → Actions → Reboot
    5. Factory reset (last resort): hold reset button 45s, wait 2min to boot
