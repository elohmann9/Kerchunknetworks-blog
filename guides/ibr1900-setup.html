🏁 Start Here: Hardware Setup
First Time? Follow these physical setup steps before trying to log into the software.
  • Power: Connect the 4-pin Molex power connector. Ensure the router powers on (Power LED solid green).
  • Antennas:
    • Connect 4x Cellular/5G antennas to "Cellular" ports.
    • Connect 2x WiFi antennas to "WiFi" ports.
    • Connect 1x GPS antenna to "GPS" port (Critical for tracking!).
  • Laptop Connection: Connect your laptop via Ethernet cable to LAN Port 1.
  • Starlink (Optional): Connect Starlink Ethernet adapter to WAN Port.

    🚀 Initial Router Setup
    Step 1: Router Access & Security
    # Initial connection URL: https://192.168.0.1 Default Login: admin / [last 8 digits of MAC address] # If login fails: Factory reset (hold button 45s, wait 1min)

    Secure Admin Password:

    • Local Router: System → Administration → Router Security
    • NetCloud: Settings → Device Settings → [Select Router] → Security
    • Set strong password: FireDept2025! (or similar)
    Step 2: NetCloud Manager Registration
    ⚠️ Security: Only whitelist specific IP addresses for SSH access. Never allow unrestricted SSH access to fire department equipment.

    Recommended Whitelist:

    • Fire HQ network: 10.0.0.5
    • IT management subnet: 192.168.1.0/24
    • Emergency management IPs only

    Test SSH Access:

    ssh admin@[ROUTER_CELLULAR_IP] # Should connect from whitelisted IPs only
    Step 3: Firewall Configuration

    Path: Security → Zone Firewall

    Required Outbound Rules:

    • Allow UDP 12121 to avl.tabletcommand.com (GPS)
    • Allow UDP 12345 to avl.smc911.org (GPS)
    • Allow UDP 53 to DNS servers
    • Allow ICMP for health checks

    Security Rules:

    • Block unnecessary inbound traffic
    • Allow SSH only from whitelisted IPs
    • Log all security events
    Step 4: SNMP Monitoring

    Path: System → SNMP Configuration

    • Enable SNMPv3 (secure version)
    • Community String: [SECURE_COMMUNITY_STRING]
    • Access: Read-only for monitoring tools
    • Allowed Hosts: Fire department monitoring systems only

    📋 Test Procedure: Document failover timing for emergency response planning.
    1. Disable cellular interface temporarily
    2. Confirm automatic switch to Starlink
    3. Verify GPS continues reporting during failover

    • GPS services continue uninterrupted
    • Automatic failback when cellular restored

    • 🚨 Troubleshooting Guide
    GPS Services Not Reporting

    Diagnostic Steps:

    1. Check GPS Status: Status → Location → GPS Status
      • Satellites: Should show 4+ satellites
      • Fix Quality: Should be "3D Fix"
    2. Test Server Connectivity:
      ping avl.tabletcommand.com ping avl.smc911.org
    3. Check Client Status: Location → GPS Clients → [CLIENT] → Status
      • Last Transmission: Should be recent
      • Packets Sent: Should be incrementing
    4. Verify Firewall Rules:
      • Allow UDP 12121 to avl.tabletcommand.com
      • Allow UDP 12345 to avl.smc911.org

    Solutions:

    • Restart GPS client: restart location-client [CLIENT_NAME]
    • Check antenna connections
    • Verify server addresses haven't changed
    • Contact dispatch center to confirm reception
    WAN Failover Not Working

    Diagnostic Steps:

    1. Verify Interface Status: Status → WAN → Interfaces
      • Both cellular and Starlink should show "Connected"
    2. Test Failover Triggers:
      • Manually disconnect primary connection
      • Monitor logs for failover events
      • Time the switchover process
    3. Check Health Monitoring: Network → WAN → Failover → Health Checks
      • Ping targets should respond
      • Adjust thresholds if needed

    Solutions:

    • Reduce failover detection time
    • Add multiple ping targets (8.8.8.8, 1.1.1.1)
    • Check physical connections
    • Update interface priorities
    WiFi Performance Issues

    Common Issues & Solutions:

    • Slow 5GHz Performance:
      • Check for channel interference
      • Adjust power levels
      • Verify band steering configuration
    • Connection Drops:
      • Check client limits (max 20)
      • Verify power supply stability
      • Update device drivers
    • Poor Range:
      • Check antenna connections
      • Adjust antenna positioning
      • Consider external antennas for fire truck mounting
    Emergency Procedures

    Emergency Recovery Steps:

      • Switch to radio backup communications

      • Test with known good cable
    3. Recovery Options:
      • Router reboot: System → Actions → Reboot

    📱 Cellular eSIM Configuration
    Step 1: eSIM Activation

    NetCloud Manager Path:

    Settings → Connectivity → Modems → [Select Router] → SIM Management

    Local Router Path:

    Networking → Modems → SIM/APN Settings
    1. Select eSIM option
    2. Download profile via NetCloud Manager
    3. Choose carrier (Telnyx recommended for fire departments)
    4. Set APN: data00.telnyx (or carrier-specific)
    Step 2: Verify Private IP Assignment
    🚨 Critical: Ensure you get a PRIVATE IP address, not CGNAT. Fire departments need direct connectivity for emergency operations.

    Verification Paths:

    • NetCloud: Status → Devices → [Router] → Connection Status
    • Local: Status → Internet → Connection Manager

    Expected Result: IP like 10.0.0.123 (private range)

    If CGNAT: Contact carrier immediately to request static/private IP

    Step 3: LAN Network Configuration

    Path: Networking → Local Networks → Local IP Networks

    Setting Value Purpose
    Router IP 192.168.10.1 Fire engine network gateway
    Subnet Mask 255.255.255.0 /24 network (254 devices)
    DHCP Range 192.168.10.10 - 192.168.10.100 Automatic device assignment
    Reserved IPs 192.168.10.2-9 Static assignments for critical equipment
    🛰️ Starlink Backup Configuration
    Step 1: Physical Connection
    1. Connect Starlink dish to WAN2 Ethernet port on IBR1900
    2. Set Starlink dish to IP Passthrough mode via Starlink app
    3. Verify connection via Starlink app shows "Connected"
    📍 Mounting: Ensure Starlink dish has clear sky view for optimal satellite connectivity during emergency operations.
    Step 2: WAN2 Interface Configuration

    Path: Networking → WAN → Interfaces

    • Set WAN2 as Ethernet interface
    • Configuration: DHCP Client
    • Priority: 2 (backup to cellular)
    • Enable interface: ✅
    Step 3: Failover Configuration

    Path: Networking → WAN → Connection Manager

    Setting Value Purpose
    Primary Interface Cellular (WAN1) Main internet connection
    Secondary Interface Starlink (WAN2) Automatic backup
    Health Check ping 8.8.8.8 Connection monitoring
    Failover Time 30 seconds Emergency response acceptable
    Auto Failback Enabled Return to cellular when restored
    📶 WiFi Configuration
    Step 1: Dual-Band WiFi Setup

    Path: Networking → WiFi → Wireless Settings

    • Enable Dual-Band Concurrent
    • 2.4GHz SSID: Public-fc
    • 5GHz SSID: Public-fc5G
    • Region: United States
    • Channel Selection: SmartSelect (automatic)
    Step 2: Advanced WiFi Settings

    Path: Networking → WiFi → Advanced Settings

    • Band Steering: Enable (automatic 5GHz preference)
    • Alternative: Use separate SSIDs with manual 5GHz preference
    • Max Clients: 20 (fire department equipment limit)
    Step 3: Fire Engine Optimization

    Path: Networking → WiFi → Client Management

    • Priority Devices: Fire tablets, emergency equipment → 5GHz band
    • QoS: Enable for emergency traffic
    • Device Priority: Critical fire department equipment first
    ✅ Optimization: 5GHz provides better performance for data-heavy applications like mapping and video streaming during emergency operations.
    🛰️ Dual GPS Configuration
    Why Dual GPS? We configure two separate GPS clients because Versaterm (CAD) and Tablet Command (Tactical) require different data formats and update intervals.
    Global GPS Settings (Main Page)

    Path: System → Administration → GPS

  • Enable GPS: ✅ Checked
  • Enable GPS Lock LED: ✅ Checked (Helps troubleshooting)
  • Enable GPS Keepalive: ✅ Checked (Prevents "disappearing" units)
  • Enable GPS verbose logging: ☐ Unchecked
  • TAIP Vehicle ID: #3302 (Your unique Unit ID)

    • Client 1: Versaterm (Dispatch/CAD)

    Versaterm Configuration
    Setting Value Notes
    Client Name Versaterm
    Server avl.smc911.org San Mateo County AVL
    Port 12345
    Protocol UDP Faster, lower overhead
    Stored Sentences 1000 ~50 min buffer
    Time Interval 3 seconds High frequency updates

    NMEA Settings (Language Page):

  • Language: NMEA
  • Prepend Unique Identifier: ✅ Checked (Critical for Versaterm!)
  • Unique Identifier Definition: Custom: "3302"
  • Sentence Types:
    • ✅ RMC (Recommended Minimum) - ONLY this one needed.
    • ☐ GGA/GNS/VTG - Leave OFF to save data.

    • Client 2: Tablet Command (Tactical Map)

    Tablet Command Configuration
    Setting Value Notes
    Client Name Tablet Command
    Server avl.tabletcommand.com
    Port 12121 Different from Versaterm
    Protocol UDP
    Stored Sentences 1000
    Time Interval 10 seconds Slightly slower update rate

    NMEA Settings (Language Page):

  • Language: NMEA
  • Include Unique Identifier: ✅ Checked (Appended at end)
  • Prepend Unique Identifier: ☐ Unchecked
  • Unique Identifier Definition: System ID (Router Serial/MAC)
  • Sentence Types:
    • ✅ GGA (Position Fix)
    • ✅ GNS (GNSS Fix)
    • ✅ RMC (Recommended Minimum)
    • ✅ VTG (Velocity/Track)
    • Optimization: Reduce Data Usage
    💡 Pro Tip: Configure "Stationary Settings" to save cellular data when the fire engine is parked at the station or a scene.

    Recommended Settings (Page 3):

    • Stationary Time Interval: 30-60 seconds (Slower updates when parked)
    • Stationary Event Threshold: 60 seconds (Wait 1 min before slowing down)
    • Stationary Distance Threshold: 20 meters (Ignore GPS "drift")

    Impact: Reduces GPS data usage by ~75% while maintaining instant tracking when the vehicle starts moving.
