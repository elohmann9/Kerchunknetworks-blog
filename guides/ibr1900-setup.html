🚀 Initial Router Setup
Step 1: Hardware Prep
  • Pull the SIM card before configuring locally. With SIM inserted, the unit tries to connect to NetCloud Manager and the local UI becomes sluggish and unreliable.
  • Antennas: 4× Cellular/5G → Cellular ports. 2× WiFi → WiFi ports. 1× GPS → GPS port.
  • Connect PC via Ethernet to LAN Port 1 — NOT the WAN port.
  • Starlink (if applicable): Connect Starlink Ethernet adapter to the WAN port.
Step 2: Router Access & Default Credentials
# Initial connection — PC connected to LAN port via Ethernet URL: https://192.168.0.1 Default Login: admin / [serial number found on the barcode label on the unit] # If login fails or config is corrupted: Factory reset (hold button 45s, wait 2 min)
⚠️ Default Password: The default password is the serial number found on the barcode label on the unit — not "admin" and not the MAC address.

Secure Admin Password after initial setup:

  • Local Router: System → Administration → Router Security
  • NetCloud: Settings → Device Settings → [Select Router] → Security
Step 3: NetCloud Manager Registration
⚠️ Critical: Register with NetCloud Manager BEFORE deployment for remote management capabilities.
  1. Go to NetCloud Manager
  2. Dashboard → Add Device → Manual Registration
  3. Enter Serial Number and MAC Address (found on router label)
  4. Device Name: "WFPD [UNIT] - IBR1900" (e.g., "WFPD E7 - IBR1900")
  5. Location: Woodside Fire Protection District
Step 4: Configuration Backup

Always backup before making changes:

  • Local Router: System → Configuration → Export Configuration
  • NetCloud: Settings → Device Settings → [Router] → Configuration → Export
  • Save as: "IBR1900_[UNIT]_Backup_YYYY-MM-DD.json"
🗺️ IP Addressing Scheme — All WFPD Units

Each apparatus gets a unique 3rd octet (X). Ops network is 10.7.X.0/24 and guest network is 10.8.X.0/24, where X is the unit's assigned octet. See table below.

📐 IP Scheme Rules:
  • Second octet = 7 (Woodside district) for ops, 8 for guest
  • Engines 1–99: unit number direct (E7 = 7, E8 = 8, E19 = 19)
  • Rescue: 20s (R7 = 27)
  • Water Tenders: unit number direct (WT108 = 108, WT119 = 119)
  • Battalion Chief: 200s (BC2 = 202)
  • 3-digit engines: hundreds×10 + ones (E307 = 37, E507 = 57)
  • Reserve engines: same formula +10 (E108 = 28, E119 = 29)

  • Gateway: 10.7.X.1
  • DHCP Range: 10.7.X.100 – 10.7.X.200

⚠️ DO NOT Manually Create VLAN Interfaces
🚨 CRITICAL — Read This Before Touching Anything:

VLAN tagging is handled automatically by the router when you assign SSIDs to local networks. DO NOT manually create VLAN interfaces for guest or scene mesh networks.

This has caused units to lose all connectivity and required factory reset. This has happened 4+ times.

The only pre-existing VLAN interfaces are: wan (VID 1) and lan (VID 2) — leave them alone. Do not rename them. Do not add more.

Assign SSIDs to the correct network via the Interfaces tab inside the SSID editor. The router handles the rest. If you think you need to create a VLAN interface manually — you don't.

If it still doesn't work after assigning the SSID correctly: Factory reset and start fresh. Don't dig deeper into VLAN settings.
📋 Safe Configuration Order — Follow Exactly
⚠️ Follow this exact sequence. Deviating — especially doing VLAN interfaces early or out of order — is how units get bricked.
Step 1 — Initial Access

Connect PC via Ethernet to LAN port (not WAN). Navigate to 192.168.0.1. Default after factory reset: username admin, password is the serial number on the barcode label on the unit.

Step 2 — Configure Primary LAN IP

Edit the Primary LAN directly — do not create a new network.

Networking → Local Networks → Local IP Networks → Edit Primary LAN

  • IPv4 Settings → change IP to 10.7.X.1 (use this unit's assigned 3rd octet from the table above)
  • Subnet Mask: 255.255.255.0
Step 3 — Configure DHCP (Same Editor — Don't Save Yet)

While still in the Primary LAN editor:

  • IPv4 DHCP → set range: 100–200 (gives range 10.7.X.100 – 10.7.X.200)
  • Custom Options → Option 6: 1.1.1.1,8.8.8.8 (DNS)

Now hit Save. You will immediately lose your browser connection — this is expected.

Step 4 — Reconnect to New IP

Unplug and replug the Ethernet cable. Your PC will receive a DHCP address automatically in the 10.7.X.100–10.7.X.200 range. No need to set a static IP on the PC.

Navigate to 10.7.X.1 to confirm it loads.

Step 5 — Add Guest Network

Add a new local network for guest traffic:

  • IP: 10.8.X.1 / Subnet: 255.255.255.0
  • DHCP range: 100–200
  • Custom Options → Option 6: 1.1.1.1,8.8.8.8
Step 6 — Add Scene Mesh Network

Add a third local network for scene mesh (same IP on all units — first unit online becomes the gateway):

  • IP: 10.7.99.1 / Subnet: 255.255.255.0
  • DHCP range: 100–200
Step 7 — DO NOT Manually Create VLAN Interfaces
🚨 Skip VLAN Interfaces entirely. The router handles VLAN tagging automatically when you assign SSIDs in the next step. Manually creating VLAN interfaces will brick the unit.
Step 8 — Configure WiFi SSIDs

Networking → WiFi → Wireless Settings

  • WFPD-[UNIT] — 5GHz, assigned to Primary LAN (ops) — e.g., WFPD-E7
  • WFPD-[UNIT]-GUEST — 2.4GHz, assigned to Guest network — e.g., WFPD-E7-GUEST
  • WFPD-SCENE — 5GHz, assigned to Scene mesh network (same SSID on all units)

Assign each SSID to the correct network via the Interfaces tab inside the SSID editor.

Step 9 — Guest Zone Firewall Rule

Security → Zone Firewall → Zone Forwarding → Add Rule

  • Source Zone: Guest LAN Zone
  • Destination Zone: Primary LAN Zone
  • Filter Policy: Default Deny All

Guest devices can reach the internet but cannot reach the ops network. One rule is all that's needed.

Step 10 — WAN Health Check (All WAN Interfaces)

Networking → Connection Manager → WAN Verify

  • Verify Method: Active Ping (do not use passive DNS)
  • Ping Target: 8.8.8.8
  • Retry Interval: 5 seconds
  • Retry Count: 3 (fails after ~15s)

Apply to all WAN interfaces (SIM and WiFi/Starlink WAN).

Step 11 — AutoQoS

Networking → QoS → AutoQoS

Verify AutoQoS is enabled — it's on by default. Leave it as-is unless there's a specific reason to change it.

Step 12 — Static DHCP Reservation (Tablet Command iPad)

Reserve 10.7.X.50 for the Tablet Command iPad using the iPad's Wi-Fi MAC address.

Networking → Local Networks → DHCP Leases → Add Reservation

Getting the iPad MAC: Settings → General → About → Wi-Fi Address. Use the Wi-Fi address — not cellular or Bluetooth.

📡 WAN Failover Configuration

Use Active Ping — not passive DNS. More reliable for detecting real connectivity loss. Both SIM and WiFi WAN should be set to Always On with strict priority failover.

Starlink Physical Connection
  1. Connect Starlink Ethernet adapter to WAN port on IBR1900
  2. Set Starlink dish to IP Passthrough mode via Starlink app
  3. Verify connection via Starlink app shows "Connected"
WAN Failover Settings

Networking → Connection Manager → WAN Verify

SettingValueNotes
Verify MethodActive PingDo not use passive DNS
Ping Target8.8.8.8Google DNS — reliable target
Retry Interval5 seconds
Retry Count3Fails after ~15 seconds
Connection StateAlways OnApply to both SIM and WiFi WAN
Smart WAN SelectionDisabledUse strict priority instead
QoSAutoQoS (default)Leave as-is

Interface Priority

  • Priority 1 (Primary): Cellular SIM
  • Priority 2 (Failover): Starlink / WiFi as WAN

Both interfaces set to Always On — router uses priority to decide routing and auto-fails over when primary loses ping verification.

Two separate GPS clients are configured because Versaterm (CAD/Dispatch) and Tablet Command (Tactical) require different data formats and update intervals.

📍 Global GPS Settings: System → Administration → GPS — Enable GPS ✅, Enable GPS Lock LED ✅, Enable GPS Keepalive ✅, Verbose logging ☐ off.

    🔐 Security & SSH Access
    Step 1: SSH Configuration

    Enable SSH Server (Local):

    • System → Administration → Local Management
    • ✅ Enable SSH Server

    Enable Remote SSH (NetCloud):

    • System → Administration → Remote Admin
    • ✅ Allow Remote SSH Access
    Step 2: SSH Access Restriction

    Path: Security → Zone Firewall → Remote Access Restriction

    ⚠️ Security: Only whitelist specific IP addresses for SSH access. Never allow unrestricted SSH access to fire department equipment.

    Test SSH Access:

    ssh admin@[ROUTER_CELLULAR_IP] # Should connect from whitelisted IPs only
    Step 3: Firewall Rules

    Path: Security → Zone Firewall

    Required Outbound Rules:

    • Allow UDP 12121 to avl.tabletcommand.com (Tablet Command GPS)
    • Allow UDP 12345 to avl.smc911.org (Versaterm GPS)
    • Allow UDP 53 to DNS servers (1.1.1.1, 8.8.8.8)
    • Allow ICMP for WAN health checks
    Step 4: SNMP Monitoring

    Path: System → SNMP Configuration

    • Enable SNMPv3 (secure version)
    • Access: Read-only for monitoring tools
    • Allowed Hosts: Kerchunk Networks monitoring systems only

    • 🚨 Troubleshooting Guide
    Lost Connectivity After Config Change
    🚨 Most likely: a VLAN interface was manually created. This has happened 4+ times. Try setting PC to a static IP in the expected subnet and hitting the gateway IP. If UI is unreachable, factory reset is the fastest path forward.

    See the VLAN Warning section — read it before trying anything else.

    Local UI Slow / Unresponsive
    ⚠️ Almost certainly: SIM is inserted. Unit is trying to connect to NetCloud Manager. Pull the SIM, wait 30 seconds, reload the UI. It will be snappy again.
    GPS Services Not Reporting

    Diagnostic Steps:

    1. Check GPS Status: Status → Location → GPS Status
      • Satellites: Should show 4+
      • Fix Quality: Should be "3D Fix"
    2. Test Server Connectivity:
      ping avl.tabletcommand.com ping avl.smc911.org
    3. Check Client Status: Location → GPS Clients → [CLIENT] → Status
      • Packets Sent: Should be incrementing

    Solutions:

    • Restart GPS client: restart location-client [CLIENT_NAME]
    • Check all antenna connections
    • Verify server addresses haven't changed
    • Contact dispatch center to confirm reception on their end
    WAN Failover Not Working
    • Verify both interfaces show "Connected": Status → WAN → Interfaces
    • Confirm Active Ping is configured — not passive DNS
    • Make sure Smart WAN Selection is Off — interferes with strict priority failover
    • Confirm both interfaces are set to Always On
    • Add multiple ping targets (8.8.8.8, 1.1.1.1) if one isn't responding
    Emergency Procedures
    🚨 Critical System Failure: If primary communications fail during emergency operations.

    Emergency Recovery Steps:

    1. Switch to radio backup communications immediately
    2. Document failure time
    3. Quick checks: power connections, antenna connections, known-good cable
    4. Router reboot: System → Actions → Reboot
    5. Factory reset (last resort): Hold reset button 45s, wait 2 min to fully boot
